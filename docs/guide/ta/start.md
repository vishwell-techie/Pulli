# தொடங்குதல்

**English:** [start.md](../start.md)

## கருவிகளை உருவாக்குங்கள்

உங்களுக்கு ஒரு C கம்பைலர், CMake, Ninja, Python 3 தேவை. விளையாட்டுச்
சாளரத்துக்கு SDL2 தேவை; அது இல்லாமலும் மற்ற அனைத்தும் வேலை செய்யும்.

```bash
# Debian, Ubuntu, Raspberry Pi OS
sudo apt install build-essential cmake ninja-build python3 libsdl2-dev
# macOS
brew install cmake ninja sdl2
```

பிறகு, Pulli கோப்புறையில்:

```bash
cmake -S . -B build -G Ninja
ninja -C build
```

முதல் உருவாக்கத்தின்போது Lua பதிவிறக்கப்படுகிறது. ஒவ்வொரு கணினியும் ஒரே
பதிப்பை ஓட்ட வேண்டும் என்பதற்காக Pulli அதைத் தானே உருவாக்குகிறது.

## உங்கள் முதல் விளையாட்டு

```bash
python3 tools/pulli.py new mygame
python3 tools/pulli.py run mygame
```

`new` இரண்டு கோப்புகள் உள்ள ஒரு கோப்புறையை உருவாக்குகிறது; `run` அதை ஒரு
சாளரத்தில் திறக்கிறது. அம்புக்குறி விசைகளால் சதுரத்தை நகர்த்துங்கள்.
Escape சாளரத்தை மூடும்.

| கன்சோல் | விசைப்பலகை |
|---|---|
| D-pad | அம்புக்குறி விசைகள் |
| A, B | Z, X |
| X, Y | A, S |
| L, R | Q, W |
| START | Enter |
| SELECT | வலது Shift |

## ஒரு விளையாட்டில் என்ன இருக்கிறது

ஒரு விளையாட்டு என்பது ஒரு கோப்புறை. இரண்டு கோப்புகள் கட்டாயம்:

- **`manifest.lua`** விளையாட்டின் பெயர் என்ன, அதற்கு என்ன தேவை என்று சொல்கிறது.
- **`main.lua`** தான் விளையாட்டு.

```lua
-- manifest.lua
return {
  id      = "com.yourname.mygame",   -- unique: your name, then the game's
  title   = "My Game",
  author  = "Your Name",
  version = "0.1.0",
  spec    = 1,                       -- the version of Pulli it was written for
}
```

`id` தனித்துவமானதாக இருக்க வேண்டும்: முதலில் உங்கள் பெயர், பிறகு
விளையாட்டின் பெயர். `spec` என்பது விளையாட்டு எழுதப்பட்ட Pulli பதிப்பு.

கோப்புறையில் உள்ள மற்ற எதுவும் விருப்பத்துக்குரியது:

| கோப்பு அல்லது கோப்புறை | என்னவாகிறது |
|---|---|
| `sprites.png` | ஸ்பிரைட் தாள்: [ஓவியமும் ஒலியும்](art-and-sound.md) பாருங்கள் |
| `map.tmx`, அல்லது வேறு எந்த `.tmx` | Tiled-இல் வரைந்த வரைபடம் |
| `sfx/*.wav` | ஒலி விளைவுகள்: பெயர் வரிசைப்படி முதல் கோப்பை `sfx(0)` இசைக்கும் |
| `music/*.wav` | இசை: முதல் கோப்பை `music(0)` இசைக்கும் |
| `palette.hex` அல்லது `palette.gpl` | Pulli-யின் நிறங்களுக்குப் பதிலாக உங்கள் சொந்த 64 நிறங்கள்: [ஓவியமும் ஒலியும்](art-and-sound.md) பாருங்கள் |
| வேறு எந்த `.lua` கோப்பும் | ஒரு module, `require("name")` மூலம் ஏற்றப்படும் |

## ஒரு விளையாட்டு எப்படி ஓடுகிறது

```lua
function init()       -- once, when the game starts
end

function update(dt)   -- 60 times a second: move things, read buttons
end

function draw()       -- after every update: draw the screen
end
```

- `init` விளையாட்டு தொடங்கும்போது ஒரு முறை ஓடும்.
- `update` நொடிக்கு 60 முறை ஓடும்: பொருட்களை நகர்த்தவும் பொத்தான்களைப்
  படிக்கவும்.
- `draw` ஒவ்வொரு `update`-க்குப் பிறகும் ஓடும்: திரையை வரைய.

`dt` என்பது கடந்த update-இலிருந்து ஆன நேரம், எப்போதும் 1/60 நொடி.
வேகங்களை அதனால் பெருக்குங்கள்; உதாரணமாக நொடிக்கு 100 பிக்சல் வேகத்துக்கு
`x = x + 100 * dt`. படிகள் நிலையானவையாக இருந்தாலும் உங்கள் நிரல் தெளிவாகப்
படிக்கும்.

பொருட்களை மாற்றுவதற்கு `update`-ஐயும் அவற்றை வரைவதற்கு `draw`-ஐயும்
பயன்படுத்துங்கள். கன்சோலுக்கு நேரம் போதாமல் போனால் அது ஒரு `draw`-ஐத்
தவிர்க்கும், ஒருபோதும் ஒரு `update`-ஐத் தவிர்க்காது; அதனால் படம் தடுமாறினாலும்
விளையாட்டு சரியாகவே இருக்கும்.

திரை 320 பிக்சல் அகலமும் 240 பிக்சல் உயரமும் கொண்டது. `(0, 0)` மேல் இடது
மூலை; y கீழ்நோக்கி அதிகரிக்கும்.

## தவறுகளைக் கண்டுபிடித்தல்

`dbg(...)` நீங்கள் விளையாட்டைத் தொடங்கிய டெர்மினலில் அச்சிடும். ஒரு மதிப்பு
என்ன என்று பார்க்க இதுவே விரைவான வழி:

```lua
dbg("score", score, "lives", lives)
```

விளையாட்டில் பிழை ஏற்பட்டால் அது நின்றுவிடும்; எந்தக் கோப்பு, எந்த வரி என்று
செய்தி சொல்லும். `print()` விளையாட்டுத் திரையில் எழுத்துகளை வரையும்; அது
டெர்மினலுக்குச் செல்லாது.

## சாளரம் இல்லாமல் சோதித்தல்

```bash
python3 tools/pulli.py check mygame        # run 600 frames, report errors and memory
python3 tools/pulli.py check mygame 3600   # a minute of game time
```

முதல் கட்டளை 600 ஃப்ரேம்கள் ஓட்டி பிழைகளையும் நினைவகத்தையும் சொல்லும்;
இரண்டாவது ஒரு நிமிட விளையாட்டு நேரம் ஓட்டும்.

## விளையாட்டைப் பேக் செய்தல்

```bash
python3 tools/pulli.py pack mygame         # writes mygame.pulli
python3 tools/pulli.py list mygame.pulli   # what is inside
```

ஒரு `.pulli` கோப்பு என்பது முழு விளையாட்டும் ஒரே கோப்பில்: நிரல், படங்கள்,
வரைபடங்கள், ஒலிகள், கன்சோல் படிக்கும் வடிவங்களுக்கு மாற்றப்பட்டவை. நீங்கள்
பகிர்வது அதைத்தான். `list` அதனுள் என்ன இருக்கிறது என்று காட்டும். விளையாட்டைப்
பற்றிய `README.md` போன்ற Markdown குறிப்புகள் கோப்புறையிலேயே இருக்கும்;
பேக்கேஜில் சேர்க்கப்படுவதில்லை.

## சேமித்தல்

சிறந்த மதிப்பெண் போன்ற ஒன்றை ஒரு விளையாட்டிலிருந்து அடுத்ததற்கு வைத்திருக்க,
manifest-இல் இரண்டு வரிகள் சேர்க்கவும்:

```lua
  save_target = "sd",    -- keep save data on the console's card
  save_size   = 1024,    -- bytes it may use, up to 65536
```

`save_target` சேமிப்புத் தரவைக் கன்சோலின் அட்டையில் வைக்கச் சொல்கிறது;
`save_size` அது பயன்படுத்தக்கூடிய பைட்டுகள், 65536 வரை.

பிறகு `save("best", score)` ஒரு மதிப்பைச் சேமிக்கும், `load("best", 0)` அதைத்
திரும்பப் படிக்கும்; முதல் முறை `0` கிடைக்கும். மதிப்புகள் எண்கள், உரை,
true/false, அல்லது அவற்றைக் கொண்ட ஒரு டேபிளாக இருக்கலாம் (டேபிள்கள் நான்கு
அடுக்கு வரை உள்ளடங்கலாம்).

விளையாட்டு முடியும்போது சேமிப்புத் தரவு எழுதப்படுகிறது; `save_commit()` அதை
உடனே எழுதும், அதனால் சோதனைச் சாவடிகளில் அதை அழையுங்கள்: புதிய நிலையை
அடையும்போது, சேமிப்பு இடத்தில், ஒரு சுற்றின் முடிவில். செயலிழப்போ தீர்ந்த
பேட்டரியோ இவற்றில் கடைசியானதற்குப் பின் சேமித்ததை இழக்கச் செய்யும்.

பின்னணியிலும் எழுத வேண்டுமென்றால், manifest-இல் இரண்டு வரிகள் சேர்க்கவும்:

```lua
  save_mode     = "auto",
  save_interval = 60,    -- seconds between writes: you choose, 10 or more (60 if left out)
```

`save_interval` எழுதுதல்களுக்கு இடையிலான நொடிகள்: நீங்களே தேர்ந்தெடுங்கள்,
10 அல்லது அதற்கு மேல் (குறிப்பிடாவிட்டால் 60). கடைசி எழுதுதலிலிருந்து (சோதனைச்
சாவடியும் சேர்த்து) `save_interval` நொடிகள் கடந்த பிறகு ஒரு மாற்றம்
எழுதப்படும். ஒவ்வொரு எழுதுதலும் flash நினைவகத்தைத் தேய்க்கிறது; அதனால்
அனுமதிக்கப்படும் மிகக் குறைந்த இடைவெளி 10 நொடிகள். ஒரு விளையாட்டு
`save_commit()`-ஐ உண்மையான சோதனைச் சாவடிகளில் மட்டும் அழைக்க வேண்டும்,
ஒவ்வொரு ஃப்ரேமிலும் அல்ல.

## தெரிந்துகொள்ள வேண்டிய வரம்புகள்

- **நினைவகம்:** உங்கள் Lua நிரலுக்கும் தரவுக்கும் 256 KB வரை கிடைக்கும்.
  `stat("mem")` எவ்வளவு பயன்பாட்டில் உள்ளது என்று KB-இல் சொல்லும். ஒவ்வொரு
  ஃப்ரேமிலும் புதிய டேபிள்களை உருவாக்கினால் நினைவகம் குப்பையால் நிறையும்;
  அவற்றை ஒரு முறை உருவாக்கி மீண்டும் பயன்படுத்துங்கள் (`pool` உதவி நிரல்
  இதற்கு உதவும்).
- **Lua:** 32-பிட் எண்களுடன் Lua 5.4. முழு எண்கள் சுமார் −2.1 பில்லியன் முதல்
  2.1 பில்லியன் வரை; அதைத் தாண்டினால் சுற்றி வரும். பின்ன எண்களுக்கு சுமார்
  ஏழு இலக்கத் துல்லியம்.
- **கோப்புகள் இல்லை:** ஒரு விளையாட்டு கோப்புகளைப் படிக்கவோ எழுதவோ முடியாது.
  அதற்குத் தேவையான அனைத்தும் அதன் பேக்கேஜில் உள்ளன; தரவை அது `save` மூலம்
  வைத்திருக்கிறது.
- **எல்லா இடத்திலும் ஒரே மாதிரி:** ஒரே விளையாட்டு ஒவ்வொரு கணினியிலும் கடைசி
  பிட் வரை ஒரே முடிவுகளைத் தரும், சீரற்ற எண்கள் உட்பட. ஒவ்வொரு முறையும்
  வேறுபட்ட சீரற்ற எண்கள் வேண்டுமென்றால், வீரர் ஒரு பொத்தானை அழுத்தும்போது
  `math.randomseed(stat("frame"))` அழையுங்கள்.
